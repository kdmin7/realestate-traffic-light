MCP SERVER DESIGN · v0.1 (draft)

서울 부동산 인사이트 MCP 서버

서울 25개 자치구를 기준 단위로, 20년치 가격 트렌드와 학군·범죄·유동인구·소득을 하나의 투명한 지표 체계로 결합하는 설계도. 기존 오픈소스 MCP는 재활용하고, 시장의 빈틈만 직접 구축합니다.

기준 단위 자치구 25 시계열 2006〜 · 분기 전략 재활용+직접 하이브리드 런타임 Node · MCP SDK ⚠ 투자조언 아님 · 지표 제공

01 설계 원칙

🧭

공간 단위 통일

서로 다른 지리 단위(지번·경찰서·행정동·시군구)를 자치구 25개로 롤업해 비교 가능하게 만든다.

🕰️

2단 시계열

가격·거래량·금리는 20년 분기 장기 코어, 소득·범죄·학군은 스냅샷+연 추세로 분리 설계.

♻️

재활용 우선

지오코딩·KOSIS 등 검증된 MCP는 그대로 붙이고, 공간통일·스코어 로직만 직접 소유한다.

⚖️

투명한 가중치

종합 스코어의 가중치는 숨기지 않고 입력 파라미터로 노출 — 판단은 사용자 몫.

📐

지수·실질 보정

단순평균 대신 실거래가격지수, 명목 대신 CPI 실질화로 20년 비교의 왜곡 제거.

04 2단 시계열 설계

Tier 1 · 장기 코어

2006〜현재 · 분기 리샘플
  • 아파트 매매가·중위가·㎡당가 국토부
  • 거래량 국토부
  • 실거래가격지수 부동산원
  • 전세가율·월세수익률 국토부 전월세
  • 기준금리·주담대금리 ECOS

Tier 2 · 스냅샷 + 연 추세

가용 기간만 · 연 단위
  • 평균 근로소득 KOSIS · 연
  • 5대범죄율 경찰청 · 연
  • 유동인구(생활인구) 서울시 · 2017〜
  • 학군 강도 학교알리미 · 현재
  • 공급(입주·미분양) 부동산원 · 월
두 티어는 절대 억지로 같은 축에 겹치지 않는다. 장기 트렌드 차트 위에 Tier 2는 "현재값 배지"나 별도 패널로 표시 — 8년치 유동인구를 20년 가격과 한 선에 그리면 왜곡이 생긴다.

06 종합 스코어 공식

score(구) = w₁·실질가격상승률 + w₂·거래량추세 + w₃·전세가율
        + w₄·유동인구증가 + w₅·평균소득 + w₆·학군지수
        − w₇·범죄율 − w₈·공급과잉
  각 항 = min-max 정규화(0〜100), 역방향 지표는 부호 반전, Σwᵢ = 1

08 구축 로드맵

PHASE 1

장기 가격 코어

가장 확실하고 임팩트 큰 것부터. 자치구별 20년 분기 가격·거래량·전세가율 + 검증(실거래가공개시스템 표본 대조).

get_price_trend · get_price_index · get_jeonse_ratio
PHASE 2

맥락 + 정주여건 스냅샷

금리 오버레이·실질보정, 소득(재활용)·범죄·유동인구·학군 스냅샷 결합, 종합 스코어 1차.

get_macro_context · get_crime_rate · get_living_population · get_school_index · get_region_income · get_district_score
PHASE 3

공급·호재 레이어 + 대시보드

입주물량·미분양, 교통·정비 호재 플래그, 그리고 전용 HTML 대시보드(반도체 대시보드 스타일).

get_supply_pipeline · get_development_catalyst · dashboard

09 한계 · 반드시 명시할 전제

⚠ 이 서버가 하지 않는 것

  • 투자 조언 아님 — "어디를 사라"를 말하지 않는다. 지표를 조회·시각화할 뿐, 가중치와 결정은 사용자 몫.
  • 과거 ≠ 미래 — 지난 20년은 저금리·상승장 비중이 컸다. 트렌드는 구조 파악용이지 수익 보장이 아니다.
  • 학군은 proxy — "서울대 진학률"은 공개 데이터가 없다. 자사고 밀도·진학률·학원가로 근사할 뿐임을 표기.
  • 공간 근사 오차 — 경찰서 관할↔자치구, 원천징수지↔거주지 소득 등 불일치가 존재. 참고 지표로 볼 것.
  • 동 단위 한계 — 소득·범죄는 자치구 해상도까지만. 같은 구 안의 동네 차이는 못 본다.
